# 首页BD提成确认表

## 交付设计

在首页“业务参考数据”下方增加“BD提成确认明细”，保留原表和原有奖金演示区。将用户提供的两行有效表头归为订单信息、确认基数、确认提点三组，末尾独立展示奖金、是否发放、是否退款和备注，忽略无名称空白占位列。

- 订单信息：季度、BD姓名、付款公司、付款时间、所购服务、首购/续费、订单金额、是否计发提成。
- 确认基数：共享订单（填写BD名）、分摊比例、奖金计算基数。
- 确认提点（结合首购/续费）：市场渠道、转介绍、累计营收、适用提点（分段提点）。
- 付款公司优先使用付款户名，空白时使用业务id信息；日期显示为年月日。
- 新服务缺少计发配置时提醒管理员设置；按服务维护计发标记和备注，单笔确认可以覆盖服务规则。
- 市场同事推荐缺少推荐人姓名时标注待补填；协会/合伙人/客户推荐从来源与补充说明识别。
- 未确认共享、基数、提点、奖金、发放和退款的单元格保持待确认，不将源文件奖金推断为新结算结果。
- 累计营收和分段提点算法尚无确定口径，不凭订单重复记录直接累计或套用比例；允许保存人工确认提点及奖金，明确区别自动核算。

## 权限与保存

只读范围使用现有BD本人/全部开关，服务端在过滤分页前限制人员。只有管理员/超级管理员可修改。服务规则和单笔确认保存在SystemSetting表，不反写CSV，修改动作进入审计日志。单笔标识绑定源内容及行号，源记录变化后不沿用旧确认；更新使用版本检查避免静默覆盖。

## 验证与运行

执行生产构建；覆盖付款公司兜底、日期格式、推荐匹配、权限、规则提醒、单笔覆盖、备注保存和版本冲突；更新后重启同源18080服务。
