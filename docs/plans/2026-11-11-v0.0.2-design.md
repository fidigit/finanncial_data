# v0.0.2 奖金表设计与交付

## 已确认范围

- 原业务参考数据表保留。
- 原BD提成确认明细拆为销售奖金表、市场奖金表，保留相同19个字段和确认记录。
- 用户授权初始随机归类8位BD；首次启动将4人分配为销售、4人分配为市场并持久化。不会随刷新、重启重新随机。
- 只有用户名为admin或梁梓珊且拥有管理员角色的账号可查看、保存身份归类。并发保存用版本号防覆盖。
- 身份与登录角色独立；修改身份影响该姓名全部历史订单的当前展示位置。新姓名等待归类；无归属订单保留在业务参考表。
- 三张奖金表的BD权限固定为本人，服务端在筛选、分页、选项和导出前执行，原参考表开关不影响奖金表。管理员查看全部。

## 会议表

保留用户提供的14列表头，包括“六重报名数”“还否发放奖金”。管理员可新增、修改；BD只读。姓名必须匹配已有BD账号，数量非负，好友通过率0–100%，奖金非负。是否达标、奖金和是否发放允许待确认；不根据两个阈值擅自生成完整奖金规则。会议记录存放于已有system_settings独立键，后续连接数据源时可替换投影与存储接口。

## 导出与展示

三个独立XLSX下载入口。导出当前筛选下全部页，按姓名分Sheet；非法Sheet字符替换、超长截断、重名加后缀，空结果提供仅表头的“无数据”页。文本写为字面值，不执行公式；金额和人数写为数值。来源记录按原始行保留，不擅自去重。

默认“摘要与详情”模式显示关键列，展开行纵向显示全部字段，免横向滚动；完整表格模式保留全部列。对比方案：强行缩窄全部列会降低可读性；按字段分多个页签便于专题核对但无法同时比较全部字段；本次选择摘要展开作为默认。

## 升级与验证

无需新增依赖和破坏性表迁移。复用现有数据库，首次启动新增身份设置，不覆盖账号、密码、服务规则和确认记录。原始数据和备份不提交Git。

验证包括原25项回归、新增身份/权限/XLSX/会议校验，共28项测试；TypeScript与Vite构建；Edge浏览器首页、详情展开、会议表单检查。
