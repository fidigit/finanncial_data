# 奖金来源与订单数据接入边界

当前运行数据源为REFERENCE_CSV_PATH指定的后台参考数据；数据库账号、表名与字段映射尚未提供，因此本次没有发起外部数据库连接。

backend/order_source.py提供read_orders和iter_orders两个入口。按用户最新要求，奖金方案只显示已保存项目，不从参考数据自动添加服务。手动新增的资格可留空并保存为null。年度订单统计仍用于年份诊断，无定时刷新。团队VIP沿用已有独立金额公式。

C订单号入口使用同一适配器，按来源行身份分页，订单号重复不合并；BD权限在数据源端先过滤，再统计、搜索及分页。管理员可以查看所有订单。

接入MySQL/MaxCompute需提供：连接方式/凭证引用、项目或数据库及表名、只读权限、分区/增量字段、稳定行主键，以及BD姓名、付款时间、所购服务、订单号、季度、付款户名/业务id、首购续费、订单金额字段映射。供应商实现必须在查询中应用owner权限，保持稳定排序和行身份，不能把分页内服务当成完整服务目录。

当前订单入口集中到适配器。奖金方案的自动发现已停用，后续数据库接入方案确认后再启用。正式数据库接入时还需让业务总览与奖金计算读取同一批次数据，避免不同入口数据不一致。

季度人员增减仅维护目标名单，不创建/停用登录账号，不删除实际订单。人员生效事件与已建立季度存于bonus_revenue_targets；从操作季度向后生效，未来沿袭遵守事件，更早季度保留。新增后的各季度目标留空待填。离职范围内不再回退到历史按人存储的目标。
